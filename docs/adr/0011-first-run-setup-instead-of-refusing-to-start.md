# First-run setup instead of refusing to start

A fresh server with only the binary starts in first-run setup, instead of exiting the way it used to. This happens exactly when the server would otherwise refuse to start: the system config is incomplete (no SMTP, no `jwt_secret`) or there is no admin. The built-in secret defaults are gone. A missing `jwt_secret` counts as an incomplete config, and a missing `reload_db_token` only turns off the token path of `reload_db`, as a missing `metrics_token` turns off `/metrics`. A config file that is broken (unparsable, or still has competition sections) still fails loudly. We chose this so that a deploy can be just the binary, while every existing deployment with a complete config never sees the wizard.

First-run setup is unlocked by a **setup token**, not given to whoever comes first and not limited to localhost. The production server binds to `0.0.0.0` behind a public domain, so first-come would let any visitor create the admin, and localhost-only can't be reached there at all. The server makes a new token on every start and logs it. It also writes the token to `einrad-server-setup-token.txt` next to the config path (mode 0600), as a clickable `<base_url>/setup?token=…` URL when a base_url is configured, and as the bare token otherwise, never as a guessed URL. The file is deleted when the setup finishes, and a normal start removes a leftover one (e.g. after a hand-made or uploaded config), logging only its path. The token is exchanged for a short-lived HttpOnly cookie and stripped from the address bar. Until the setup is done, every page serves the setup screen and every other API answers 503, so nothing half-configured is reachable. Ansible prints only the token file's path, because deploy logs may end up in CI.

Only what's missing can be filled in. If the system config is already complete and only the admin is missing, the other steps are "not needed" and the completion rejects input for them (base_url, SMTP, metrics) with a 422 instead of silently dropping it. Values set by CLI flags or the environment are shown as "set by environment" and never written, because they would override the file anyway. Secrets are generated at random and never shown, except an opt-in metrics token, which is shown once. The wizard writes `config.toml` atomically at the config path with mode 0600, together with the commented-out advanced settings. It never overwrites an existing file. If the file can't be written, it offers the content to copy instead. The admin goes straight into the database (hashed), not into `[admin]`; the file only notes in a comment that the first-run setup created it.

Saving switches the running process into normal mode on the same listener (new `Settings`, new JWT keys and mailer), logs the admin in with a cookie signed by the new secret, and opens setup mode for the competition. It doesn't exit and rely on a supervisor to restart it, because a bare binary has no supervisor and supervisord counts an early exit as a failed start. Because of this, `http_address`, the database and the data path aren't wizard fields: they are already in use when the wizard runs. Completion runs behind one lock in this order: validate in memory (including everything the handover could refuse without side effects: the SMTP setting, a present competition file, the photos client, so bad input fails with a 422 before anything is saved), write the file, insert the admin, delete the token file, hand over. Any partial failure therefore leaves a state the trigger rule already covers.

This qualifies ADR 0005 without changing it: the system config stays file- and environment-based, and the wizard only writes that file. Ansible no longer checks for a config (`config_check.yml` is gone) and deploys bare instances. It uploads a local config or competition file only when that is explicitly requested (e.g. `-e cup_config_src=config.production.toml`), and then replaces the server's copy, because the explicit request is the intent.

Errors and log lines of the setup never echo credentials: URL userinfo (`smtp://user:password@host`) and the SMTP password and JWT secret are replaced by `***`.
