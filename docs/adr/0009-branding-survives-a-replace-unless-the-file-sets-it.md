# Branding survives a replace unless the file sets it

A replace (`--replace-competition` or the import in the admin UI) writes the competition's settings from the file, so a setting the file leaves out is cleared (ADR 0005). The branding (the logo, #286, and the primary and secondary colors, #287) is the exception: a setting the file leaves out is kept, an empty string (`logo_svg = ""`, `primary_color = ""`) resets it to the default built into the binary, and any other value sets it. We chose this because the branding is usually set in the admin UI, and a raster logo can't be in the file at all (only SVG fits into TOML): clearing it on every replace would make the organizer upload it again after each fix to the timeplan. TOML has no null, so the empty string is how a file says "back to the default".

The logo lives in its own table, not in the competition's row, so competition queries never read image bytes. An SVG logo is stored as it was uploaded or written in the file, after a check that it can't run scripts or load other files, and is served with a restrictive Content-Security-Policy; raster logos are scaled down to 512 px and lose their metadata. The export writes an SVG logo as `logo_svg` and leaves out a raster logo with a note, so an export imported into the same database keeps it.

The colors live in the competition's row (`primary_color`, `secondary_color`; NULL is the default) and are only `#rgb` or `#rrggbb` in any case, stored and exported as lowercase `#rrggbb`, so nothing but a color reaches CSS. Every page links `/api/competition/colors.css` after style.css, served like the logo (`no-cache` with an ETag). It declares `--competition-primary-color` and `--competition-secondary-color`, which style.css takes its base colors from, with its defaults as the fallback (ADR 0008). They are properties of their own, not `--color-primary`, because the build puts the bundled style.css after that link, and its `:root` rule would win; writing the colors into index.html instead would make the static, embedded page dynamic and miss the dev server, which serves its own index.html. No color is refused for its contrast: the derived colors keep texts readable whatever the base colors, and the admin's preview only warns about a color below 3:1 on white. Browsers without relative colors keep the default colors, as their fixed palette only fits those. The export writes the colors a competition sets and leaves out default ones, like a missing logo.
