# The database is the source of the competition, the competition file only an import

The competition's settings (dates, fees, payment, jury rules, photos and features) live in the database and are edited in the admin UI while the server runs, also while the registration is open. The competition file (`competition.toml`), separate from the system config, is only an import: it's applied when the database has no competition yet, or on purpose with `--replace-competition` or the import button, and a differing file at startup is ignored with a warning. Editing `competition.toml` and restarting therefore changes nothing on a running competition. We chose this over the earlier "the config's `[competition]` is written on every start" because edits in the UI would otherwise be undone by the next restart, and over keeping the file authoritative because the organizer needs to change the competition without server access.

The system config (`config.toml`: server, database, SMTP, auth, admin) stays file and environment based; its `[features]` only give the defaults for features a competition leaves unset. ADR 0001 still holds: one competition per database, and a replace keeps the competition's id.
