# Heats and finals have a readable name and a short code

Until #347 a heat or final had one `name` that was both a label and the reference: slot groups, the timeplan and the competition file all used it ("E EM 1"), and the longer text lived in an optional `description`. That name was too short to read in the jury registration ("E EM 1 Vorlauf") and too long to repeat everywhere a heat is mentioned. Heats and finals now have two names (amends ADR 0016, which kept `name` as the label and file reference).

**Name and code.** The `name` is what a person reads: "Einzel männlich – Expert 1 (U17–U21)" for a heat, "Finale Einzel männlich Expert" for a final. It shows in the jury registration (club and admin, jury plan, remap list: "<name> · Vorlauf" for a heat, the name for a final), the structure tree, the heat and final editors, the Vorlaufklasse column of the categories editor, and for a final's block in the timeplan, the startlist and the info board. The `code` is the short form, "E EM 1" or "E EM": it labels finalist slots ("1. Finalist (E EM 1)") and slot groups ("4 × E EM 1"), and it is the reference in competition files. The `description` stays an optional extra.

**Both are unique, per table.** The name was already the primary key; the code gets a unique index on `heats` and on `finals`. A heat and a final may share a code. Renaming either, or recoding it, changes one row: every reference is by id (ADR 0016).

**Migration.** The readable name becomes the existing `description` where there is one, else the current name; the code becomes the current name, and a description that moved into the name is cleared. A description another heat (or final) has too, or that equals another one's name, stays a description (the name keeps its old value), so no migration fails on a duplicate. The down migration writes the code back as the name and moves a differing name into an empty description. A row inserted without a code (older code paths, tests) takes its name as its code, by trigger.

**API.** `add_heat` and `add_final` take `name` and an optional `code`; without one, the name is the code. `edit_heat` and `edit_final` take `new_name` and an optional `new_code`; without one, the code stays. The lists, the structure tree and the jury units return both.

**Competition file.** `[[heats]]` and `[[finals]]` have `name` and an optional `code` (without it, the name is the code, so older files keep working). A reference names the **code, never the readable name**: a slot's `heat = "E EM 1"`, a timeplan entry's `final = "E EM"`. Accepting either would make a file ambiguous as soon as one heat's name equals another's code; the import error names the code it did not find. The export writes both and references by code. The remap file's `jury_unit = "heat: <name>"` and `"final: <name>"` are the readable names, as jury units show them. A replace from a file recreates heats and finals as before (ADR 0016).

**Structure tree.** All levels stay (discipline, final, heat, category, act). Each node carries a badge with its level ("Disziplin", "Finale", "Vorlaufklasse", "Kategorie", "Kür") and a legend explains them at the top; final and heat nodes show the readable name with the code small next to it where it differs.
