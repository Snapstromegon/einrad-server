# Images come from an SVG, an upload or a URL, and are served from a local copy

The competition has three kinds of images (#291): the logo (#286), the break image the info board shows while no act runs, and the sponsor logos in its footer, an ordered list of entries with an image, a name (alt text, label in the admin UI) and an optional link. They extend ADR 0009: the branding survives a replace unless the file sets it. A file's `logo_svg`/`logo_url`, `break_image_svg`/`break_image_url` and `sponsors` keep what the database has when left out, an empty string resets the logo and break image, and `sponsors = []` removes the sponsors. A sponsor in the file without `svg` or `url` keeps the image of the sponsor of the same name that's already in the database, so an export imports back into the same database without losing an uploaded raster image (which can't be in the file); otherwise it has no image and isn't shown.

An image has one of three sources: an inline SVG (in the file or pasted in the admin UI), an upload (raster or SVG, admin UI only) or a URL. The server downloads a URL image at startup, when the admin sets the URL, after an import and with the "Bilder aktualisieren" button in competition management, and always serves its local copy, never the URL: browsers don't depend on another server, and the competition's venue may have no internet. A download gets the checks of an upload (SVG safety check, raster images scaled down to 3840 px on the long edge and never up, metadata stripped; an SVG is 1 MiB at most, any other image 20 MiB), and the content tells the format, not the content type (a raw file on GitHub is `text/plain`). If a download fails, the last good copy stays and competition management shows a warning with the reason. Setting a different URL keeps the old image (an SVG, an upload or the copy of another URL) until the first good download of the new URL replaces it, so a typo costs nothing; only an image that never had any bytes falls back to the default (a sponsor has none and isn't shown). The startup download runs in the background with a 30 second limit per image, so an unreachable URL neither delays nor fails the start.

All images are rows of one table, `competition_image` (`kind` logo, break or sponsor), not part of the competition's row, so competition queries never read image bytes. A URL source keeps its last download in the same row (`data`), with when and why the last download failed. The competition file exports a URL source as its `_url`, an inline SVG as `_svg` and leaves out a raster image with a note, so URL sources round-trip without their bytes. A download that finishes after the admin changed or removed the image is dropped (the result is only stored if the image still has that URL). Refreshes run one at a time.

Without a break image the info board shows the logo, and without that the break image built into the binary. Without sponsors the info board has no footer. The sponsor logos the NRW cup used (GWN, Heiner Weiss) stay in the binary only as presets the admin can add as sponsors.

## Consequences

The server fetches whatever URL an admin (or a competition file an admin imports) names, including addresses in its own network, and shows the result as an image. Admins are trusted (ADR 0003), so we don't block private addresses, which would also break a local test server; we limit redirects to three, allow only `http` and `https` without credentials in the URL, cap the size while streaming and never show error text from the response, only the status or kind of failure. Raster images are scaled to at most 3840 px (4K) on the long edge for every kind, so one rule holds and a break image stays sharp on a large display; a decoded image is capped at 4096 px per edge against images that are small as a file but huge in memory. The 20 MiB cap (raised from the 1 MiB of ADR 0009, which still holds for an SVG) makes the request limit of the commands 21 MiB. Images are served whole from the database with an ETag, so browsers fetch a large image once.
