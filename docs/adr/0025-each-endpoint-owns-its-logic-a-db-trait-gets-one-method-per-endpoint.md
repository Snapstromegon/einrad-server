# Each endpoint owns its logic; a Db trait later gets one method per endpoint

A command or query handler holds its whole logic, SQL included, so reading one file shows everything the endpoint does (#419). We don't build an ORM-like layer of per-table getters and setters (`heats::name_of`, `fee_waivers::set_waiver`, …); the existing ones move back into their handlers. This is deliberate: a reader would expect a shared data layer, and agents keep adding one.

**Shared rules stay shared, if pure.** A rule several endpoints need (name normalization, fee calculation, timeplan prediction) is a pure function in a domain module, with unit tests, and does no SQL and returns no `HttpError`. Copying it into every handler would let the copies diverge. Access checks (`ensure_club_access` & co.) are authorization, not domain logic: they move to the extractor layer.

**The Db trait follows the endpoints, not the tables.** When the Db trait comes (#238 for Postgres and in-memory backends, #370 for multi-event, ADR 0024 for the event-sourcing seam), each handler's SQL moves into **one trait method named after the endpoint** (`assign_judge` → `db.assign_judge(…)`, `list_acts` → `db.list_acts(…)`), and its transaction moves with it. This holds for **queries as well as commands**: ADR 0024 only names write commands, but a second backend needs the reads behind the trait too, and under event sourcing they read projections. A backend only loads facts and writes (decided for #238): a rule or authorization decision that is buried in a handler's SQL is pulled out as a pure function on the way, so every backend applies the same rule. The handler keeps HTTP: extractors, authorization, body checks, the response. Until the trait exists, new endpoints write their SQL in the handler.

**Considered options.** Going straight to the Db trait now (skipping #419) would pull the #238/#370 work ahead of the LM 2027, in larger PRs. Keeping the helper modules as the domain layer would grow exactly the ORM-like surface the trait must not have, and the trait would then mirror tables instead of endpoints. Doing #419 first isn't wasted work: it produces the per-endpoint units that become the trait's methods.
